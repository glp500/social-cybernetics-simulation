# Project 1 Reading Guide

This guide is an orientation map for understanding Project 1 before changing code or interpreting
results. It does not replace the frozen specification, analysis plan, or evidence manifests.

## What Project 1 is

Project 1 is the ecological and material control for the programme. It asks what unequal provisioning,
subsistence risk, and persistent material advantage can arise from renewable resources, mobility,
competition, disturbance, and recovery alone.

It contains no learning, information inequality, social network, institution, market, ownership,
household, class, or demographic mechanism. This boundary is central: a pattern can be generated by
Project 1 without being an explanation of that pattern in a real society.

The dependency rule is `CLI/config/visualization → Mesa runtime → domain`. Analysis consumes
published records and never steps a model. The domain imports neither Mesa nor artifact libraries.

## One tick, from theory to evidence

| Stage | Executable entry | What changes | Evidence consequence |
| ---: | --- | --- | --- |
| 1. Recovery | `apply_recovery` | Existing cell-local recovery clocks advance. | Effective ecological arrays change; no new damage is recovered. |
| 2. Regeneration | `relax_resources` | Stock moves toward effective capacity. | Stock remains bounded by baseline capacity. |
| 3. Shock | `_advance_shocks` plus pure ecology functions | Events propagate/initiate and simultaneous cell damage is applied. | Shock snapshots, exposures, and authoritative damage rows append. |
| 4. Observation | `direct_observation` | Each living agent receives exact local stock. | The value enters its transition record. |
| 5. Belief | `copy_observation` | Belief copies observation without aliasing. | Observation and belief remain distinct contracts. |
| 6. Intent | `literal_local_policy` | Harvest above threshold; otherwise select a random neighbour. | Intent and request are recorded before resolution. |
| 7. Gate | `allow_all` | Every v1 intent is admitted. | The identity-like control stays measurable and replaceable later. |
| 8. Resolution | `resolve_actions` | Harvest is allocated simultaneously; moves have no collision rule. | Resource stock, harvest, and movement results become authoritative. |
| 9. Metabolism | `apply_metabolism` | Harvest converts to energy; costs are deducted. | Energy, shortfall, and death flag enter the transition record. |
| 10. Mortality | Mesa wrapper removal | Dead agents leave activation but stay in the cohort archive. | Death events and later dead cohort snapshots remain available. |
| 11. Measurement | `_measure` and spatial sink | The completed model/cohort/spatial state is recorded. | Tick history is complete from tick zero through the final tick. |

`SugarscapeModel.step()` is intentionally linear and longer than a conventional application method.
Its numbered blocks are a scientific audit trail. The equations remain in pure domain functions;
the method owns ordering and record assembly.

## State distinctions that prevent common mistakes

- `baseline capacity` is the undamaged resource attractor and never changes during a run.
- `effective capacity` is the damaged/recovering attractor.
- `resource stock` is extractable material and may temporarily exceed effective capacity after damage.
- `baseline regeneration` is fixed; `effective regeneration` can be suppressed and recover.
- `energy` is an abstract agent viability stock, not stored wealth or consumption.
- agent `position` is authoritative in the Mesa cell; snapshots combine it with domain state.
- active Mesa agents and the original cohort are different populations after mortality.
- a tick is a transition index, not an independent statistical replicate.
- a seed is the experimental replicate and the unit used for paired contrasts.

## Randomness and reproducibility

The run seed creates stable NumPy `SeedSequence` substreams:

- policy/movement `(1,)`;
- shock initiation `(2, 1)`;
- shock location `(2, 2)`;
- shock transmission `(2, 3)`.

This separation matters when comparing mechanisms. A sham shock can consume ecological draws without
shifting agent movement, and a propagation change cannot shift later event-initiation draws. The
registry and generator identity are stored in provenance. Global random calls are forbidden by an
architecture test.

## From run records to Project 1 results

A successful run bundle contains normalized configuration and provenance, a summary, full spatial
history, and seven Parquet tables. `agent_transitions.parquet` is the principal agent-level evidence:
one row records the observation, belief, intent, gate, physical result, energy change, shortfall, and
mortality for one active agent-tick.

The analysis layer then produces:

1. one raw outcome vector per run;
2. descriptive summaries for each experiment condition;
3. every declared all-pairs, within-seed condition contrast.

The frozen bundle has 140 raw outcomes, 448 condition–measure summaries, and 4,480 paired contrasts.
JSON and Parquet forms are cross-validated, and summaries and contrasts are recomputed from raw rows
during validation.

## How to inspect a result responsibly

Start with a raw outcome vector, not a condition mean. Then:

1. confirm its experiment, condition, seed, duration, and configuration digest;
2. compare the same seed across conditions;
3. inspect definedness metadata before interpreting null rank measures;
4. check the complete vector—harvest, survival, need, inequality, persistence, and ecology;
5. use transition records to identify the responsible action and allocation path;
6. use spatial history and damage records to identify the ecological path;
7. compare the explanation with the frozen alternative explanation and prohibited conclusion.

Do not combine the outcome vector into an unregistered score. Do not treat agents or ticks as
independent replications. Do not infer a social mechanism from a pattern generated without one.

## Suggested Project 1 update/data round

Use the frozen artifacts as the starting point; rerun only when verifying reproducibility or opening a
new study version.

```bash
# Validate the existing evidence in Python.
python -c "from pathlib import Path; from social_cybernetics.batch import validate_batch_bundle; validate_batch_bundle(Path('results/project1-batch'))"
python -c "from pathlib import Path; from social_cybernetics.analysis import validate_project1_analysis_bundle; validate_project1_analysis_bundle(Path('results/project1-analysis'))"

# Reproduce into absent destinations when required.
just project1 results/project1-batch-reproduction
just project1-analysis results/project1-batch-reproduction results/project1-analysis-reproduction
```

For the update, report:

- artifact identities and validation status;
- raw replicate distributions and defined/undefined counts;
- paired-seed differences, including sign variation;
- the mechanism trace supporting each headline pattern;
- competing explanations and sensitivity limitations;
- absent mechanisms and prohibited translations;
- whether the evidence motivates a Project 1 schema change or belongs in Project 2.

Never overwrite a frozen evidence directory. Publication is fail-closed and deliberately refuses an
existing destination.

## Safe change boundaries

- Change equations only in the domain and reopen the scientific specification and regression fixtures.
- Change scheduler order only in `SugarscapeModel.step()` and reopen the scheduler/specification gate.
- Add a record field by versioning the domain contract, Arrow table, bundle, readers, and validators.
- Add a metric by defining its equation, edge cases, and replicate unit in the analysis plan first.
- Add a study condition in the Project 1 experiment schema only if it remains within Project 1's
  ecological-material ontology.
- Put perception, learning, or private adaptation in Project 2; put communication, trust, diffusion,
  or circulation in Project 3. Do not add dormant future fields to Project 1 state.
